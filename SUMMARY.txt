                           TECHNICAL CHANGES AT A GLANCE
================================================================================

BACKEND API (services.py):
  OLD: Citizens auto-filtered to their ward only
  NEW: Citizens can view all wards (unless ward_id parameter specified)
  
  GET /emergency endpoint logic:
  - If ward_id provided → Filter to that ward + citywide services
  - If ward_id null → Return ALL services (all wards + citywide)
  - Role-based access still enforced at API level
  - Ward admins behavior unchanged (restricted to their ward)

FRONTEND UI (emergency_screen.dart):
  NEW COMPONENT: Ward Selector Dropdown
  - Placed at top of Emergency Services screen
  - Shows "All Wards" by default
  - Lists all available wards
  - Updates service list on selection change
  
  NEW STATE: _selectedWardId
  - Tracks current ward selection
  - null = all wards
  - 1,2,3... = specific ward
  
  NEW METHOD: _onWardChanged(int? wardId)
  - Handles ward selection changes
  - Updates state and reloads services

                              HOW TO USE
================================================================================

FOR CITIZENS:
  1. Open Emergency Services
  2. See "Select Ward" dropdown at top
  3. Choose "All Wards" or specific ward
  4. Services load for selected ward
  5. Click on service to call, email, or navigate
  6. File complaints → Ward auto-assigned (cannot change)

FOR WARD ADMINS:
  1. Open Emergency Services
  2. No ward selector (restricted to their ward)
  3. See only their ward's services
  4. All other features work as before

FOR SUPER ADMINS:
  1. Full access to all services
  2. Can manage any ward
  3. No restrictions
